# Fresh 1,000-cycle AlphaZero combat run

Server root: `/public/maxim/Codex/spire-mentor-az16384-fresh-20261024/`

The run starts from newly initialized weights, not benchmark, v30/v31, or smoke-trained weights. The network remains a four-layer width-128 transformer. Its semantic catalog covers the current native enemy moves; the name embedding table was resized to avoid namespace overlap. The production model has 1,593,346 parameters. `initialization.json` records the configuration and initial-weight checksum.

## Training settings

- 1,000 cycles, exactly one optimizer update per cycle: 1,000 updates total.
- Effective batch 16,384 decision examples: 64 microbatches of 256.
- Average microbatch gradients with weight 1/64; clip once after all 64 backward passes; then perform one AdamW step. AdamW moments, step count, and weight decay advance once per effective batch.
- Policy cross entropy against the improved Gumbel policy, plus value MSE against the v30 shaped return. Learning rate 3e-4, weight decay 1e-4, gradient norm clipping 1.0, BF16 forward/backward and FP32 parameters/gradient accumulation.
- 80 Rust simulation/search workers; 16 simulations per decision; inference batch up to 128. Collection and learning alternate on the L40. Actor weights remain frozen during each cohort and publish at its end.
- One new 1,024-start full-corpus refill bank per cycle. Unsupported imported starts are recorded by source identity, never silently modified. The number of decision examples varies with combat length. Capped training trajectories are discarded and counted.
- 65,536-state GPU replay, FIFO replacement; older targets are retained unchanged until overwritten. Each microbatch draws a token-length bucket proportional to its stored population, then samples with replacement within the bucket.

Each of the 16,384 examples is a real decision root from a completed combat, not an extra search node. Across 1,000 updates the learner consumes 16,384,000 sampled examples; these are not necessarily distinct.

## Individual potion penalties

Every training combat draws an independent Uniform[0,1] penalty for each potion instance. A potion retains that value through the combat, observation encoding and all search clones. Generated potions receive new instance identities and fresh draws. Spent penalties remain in the reward context after consumption. The return is:

```
win + 0.5 * (ending_HP / starting_HP) * (1 - sum(consumed potion costs))
    + (0 if win else 0.05 * damage_fraction)
```

HP ratio and summed cost are not clipped. Damage fraction follows v30's minimum-HP tracking for the original enemies. The value head is linear.

## Full held-out validation

Validation runs at optimizer updates 100, 200, ..., 1,000, plus a baseline before training. Each full evaluation consists of the existing 4,096 immutable held-out human combat starts run twice: 8,192 complete combat rollouts. The 1,815 source human runs remain excluded from training.

Per the latest request, both replicates use independently randomized **per-potion** costs, replacing the old fixed-cost pair. These random costs, starting states, environment/search seeds and replicate identities are frozen across checkpoints. Validation retains the current 16-simulation search budget. It does not enter replay or update weights. No failed validation case is replaced or dropped; summaries retain the full denominator and report unresolved cases if any. The startup gate requires all 8,192 to complete.

Production baseline: 3,504 wins / 8,192 combats = 42.7734%, zero unresolved. Smoke-test validation also completed the full panel; its weights were discarded.

## Data feeder and recovery

The source is the existing full-corpus sampler, not the late-act 8196 benchmark. It samples generated and eligible human starts 50/50 from the full catalogs. Previously converted banks are reused with checksum verification; new banks beyond the cached 501 are generated by an eight-worker CPU feeder. Conversion of bank 1000 was verified before launch. The producer prepares compatible native fixtures ahead of training and records exclusions.

Checkpoints are saved every ten cycles, before/after scheduled validation, and on a requested stop. They preserve learner and actor weights, optimizer moments/step, replay, sampling RNG, Torch/CUDA RNG, cycle and last validated update. Two replay checkpoint generations are retained. A crash can require replaying up to nine uncheckpointed cycles. Resume archives uncommitted progress rows and continues from the committed cycle. The supervisor allows at most three trainer attempts and respects the run's `STOP` file.

To request a graceful stop, create `/public/maxim/Codex/spire-mentor-az16384-fresh-20261024/STOP`. The trainer finishes its current work boundary, saves its state, and exits; the feeder and supervisor also honor that file. This affects only this run.
